# First BDI reader — completing issue #3

Issue: #3 (slim ingestion base). PR #111 landed the foundation (`e97bfcc`); this branch
finishes #3 by shipping the proof-of-concept reader that runs end-to-end on it, and hardens
provenance first.

## Done

- [x] **Provenance covers every artifact of a multi-artifact read.** Added
      `_internal/utils/provenance.hash_artifacts(seq_paths)` — a digest **of the per-artifact
      hex digests** (never concatenated bytes, so a 500-page read is not held in RAM),
      order-sensitive, and always composite even for N=1. The BDI base now hashes **all** pages
      including the terminating empty one, not just page 1.
      - The bug it fixes: `content_hash` exists so the lake can detect a changed source without
        re-parsing. Hashing page 1 only meant a dataset whose page 1 was byte-identical but whose
        page 3 drifted produced the **same** hash — the lake reports "unchanged" for a changed
        source. A partial fingerprint is worse than none: none is visibly absent, a partial one is
        confidently wrong.
      - Caught **before** any reader shipped, so no bronze rows exist under the partial scheme.
- [x] `tests/unit/test_provenance.py` — 14 tests; the seam had **zero** coverage in this repo.
      Includes the drift assertion (mutate a *later* artifact, assert the composite changed)
      rather than a golden digest, which would pass just as happily with the buggy version.
- [x] End-to-end drift test in `test_base_bdi_reader.py`. **Mutation-verified**: reverting the
      base to `list_pages[:1]` turns it red.
- [x] BlueprintX lesson: amended `ingestion-stamps-url-updated-at-provenance` (the authoritative
      provenance spec) rather than adding a second file, plus README index + repo mirror.
