# First BDI reader — completing issue #3

Issue: #3 (slim ingestion base). PR #111 landed the foundation (`e97bfcc`); this branch
finishes #3 by shipping the proof-of-concept reader that runs end-to-end on it, and hardens
provenance first.

## Done

- [x] **Provenance covers every artifact of a multi-artifact read.** Added
      `_internal/utils/provenance.hash_artifacts(seq_paths)` — a digest **of the per-artifact
      hex digests** (never concatenated bytes, so a 500-page read is not held in RAM),
      order-sensitive, and always composite even for N=1. The BDI base now hashes **all** pages
      including the terminating empty one, not just page 1.
      - The bug it fixes: `content_hash` exists so the lake can detect a changed source without
        re-parsing. Hashing page 1 only meant a dataset whose page 1 was byte-identical but whose
        page 3 drifted produced the **same** hash — the lake reports "unchanged" for a changed
        source. A partial fingerprint is worse than none: none is visibly absent, a partial one is
        confidently wrong.
      - Caught **before** any reader shipped, so no bronze rows exist under the partial scheme.
- [x] `tests/unit/test_provenance.py` — 14 tests; the seam had **zero** coverage in this repo.
      Includes the drift assertion (mutate a *later* artifact, assert the composite changed)
      rather than a golden digest, which would pass just as happily with the buggy version.
- [x] End-to-end drift test in `test_base_bdi_reader.py`. **Mutation-verified**: reverting the
      base to `list_pages[:1]` turns it red.
- [x] BlueprintX lesson: amended `ingestion-stamps-url-updated-at-provenance` (the authoritative
      provenance spec) rather than adding a second file, plus README index + repo mirror.

- [x] **Pagination is now DECLARED, never assumed** — a bug found by auditing the 38 BDI
      modules' actual behaviour rather than trusting the uniform `…/<page>/<pageSize>` URL:

      | stpstone `int_page_max` | Count | Meaning |
      |---|---|---|
      | `1` | 32 | single-page |
      | `None` | 5 | genuinely paginated |
      | flagged non-paginated | 3 | **echoes the same rows for every page number** |

      The base looped until `values` was empty, so against those 3 echoing endpoints it would
      have appended the same rows once per page to the 500-page ceiling — silent corruption no
      contract check catches, since every duplicated row is individually valid. Now
      `int_max_pages: int | None = 1` (matching the 32-dataset majority), plus a digest-compare
      backstop that stops on the first repeated page. **Mutation-verified**: disabling the
      guard turns 2 rows into 1 000.
- [x] First concrete BDI reader — `daily_bulletin/stocks_summary.py::BdiStocksSummaryReader`
      (`DailyAverageStocks`), issue #40. Four declarations, no implementation: the section base
      supplies the rest.
- [x] `_internal/config/contracts/bdi_stocks_summary.py`.
- [x] Re-exported from `daily_bulletin/__init__.py` and the package root; `_PUBLIC_SURFACE`
      widened deliberately in `tests/unit/test_api_boundary.py` — **gate 1 working as designed**:
      publishing a name is impossible without an explicit, reviewable edit.
- [x] `example_source.py` deleted (real contracts exist — the rule that retired
      `example_port.py`). `test_base_pregao_reader` now builds its own throwaway contract rather
      than depending on a scaffold example meant to be removed.
- [x] **Every source column is typed, not just the contract's.** A test surfaced that
      `COL_ORDER` — sent by the source, absent from the contract — was reaching the frame with a
      pandas-inferred dtype. A contract lists what consumers *depend on*; extra columns still
      flow through, so `dict_dtypes` must cover all of them or the bronze schema shifts between
      sessions (an all-integer page vs one with a null). Now asserted by a test.

- [x] **Binary floats banned for ingested values, enforced by a gate.** `VLM_TRADED_DAY` (a
      session's traded financial volume, in BRL) was typed `float64`. Measuring showed the loss
      happens **upstream of the dtype**: `json.loads` already parses `1984223115.42` into a float
      holding `1984223115.4200000762939453125`, so changing the dtype alone fixes nothing.
      - `parse_float=Decimal` at the JSON boundary; `list_decimal_cols` threaded through
        `apply_dtypes` → `read_table`/`_finalize` → both section bases.
      - `_to_decimal` **refuses** a float rather than converting it — converting launders a lossy
        value into a type advertising exactness, worse than the float because nothing downstream
        questions it. `NaN` is recognised as *missing* first, since it is a float and is pandas'
        missing marker.
      - The source's own scale is preserved, never chosen: `"1.50"` stays 2dp, `"1.5000"` stays
        4dp. Quantising is a silver/gold decision.
      - `bin/check_dtypes.py` + entries in **both** `.pre-commit-config.yaml` and
        `.github/workflows/tests.yaml` (ruff cannot see a `"float64"` string literal in a dict).
        Escape hatch `# dtype-ok: <reason>` for a genuinely dimensionless value.
      - **The gate paid for itself on its first run**, catching `"price": "float64"` in the
        pregão base's *docstring example* — the worst place, since it teaches the wrong pattern
        to all 42 readers copied from it.
      - Lesson: `no-binary-float-for-ingested-values` (store + README + repo mirror).

- [x] **Backported.** BlueprintX PR **#106** (issue #105) ports `list_decimal_cols`,
      `_to_decimal`, `bin/check_dtypes.py` and both gate registrations into
      `templates/python-common`; verified with the real scaffold harness (`lib-minimal` 43 tests,
      `mvc-service-native-db` 193 tests) and mutation-tested inside the scaffolded tree.
      filings-cvm follow-up filed as `guilhermegor/filings-cvm#157` (float-free by convention
      today, but no gate and no `parse_float` guard). Lesson `ci-python-gates` amended: the gate
      *enumeration* is what goes stale.
