# PR gate never enabled auto-merge

Issue: #114. Surfaced when Dependabot PR #1 (`risk:ci`, `size:S`, green CI) sat open, and the
same turned out to be true of #111, #112 and #113 — all merged by hand.

## Three independent bugs, all silent

1. **The `lint` axis matched no check run.** The gate maps axes to check-run *name prefixes*:
   `"lint": ("Ruff", "mypy", "lint")`. But `ruff check`, `ruff format --check` and `mypy` ran as
   **steps inside** the `Run Automated Tests` job, so no check run ever carried those names. By
   the gate's own rule — *an axis with no check-run is pending, never a failure* — the axis was
   pending **forever**. Evidence, from the gate's own log on #1:

   ```
   risk=ci size=S eligible=True state=pending      # after polling 01:15:47 → 01:28:44
   ```

2. **`code scanning` hung on Dependabot PRs.** CodeQL posts its umbrella check but spawns no
   `Analyze (…)` runs there, and the axis matches only `Analyze`. Same forever-pending outcome.

3. **The `enablePullRequestAutoMerge` mutation failed silently — the real blocker.** GraphQL
   answers **HTTP 200 even when a mutation fails**; the reason lives in the body's `errors` key.
   `_api` only warns on 4xx/5xx, and the caller **discarded the return value entirely**. So a
   rejected mutation was indistinguishable from a successful one, and `eligible=True` diverged
   from "auto-merge is actually on" for every PR with nothing anywhere saying so.

Bugs 1–2 froze the sticky comment; bug 3 is why nothing merged. Fixing only 1–2 would have
produced a green comment and still no merge.

## Done

- [x] `lint` is now its own CI job (`tests.yaml`), so it emits a check run named `lint` that the
      existing axis matches. It also runs **once** instead of once per Linux matrix leg — the
      three steps were removed from the matrix job rather than duplicated.
- [x] `collect_axes` takes optional **absence sentinels**: when an axis's own checks are absent
      but its sentinel has *completed*, nothing is in flight and the axis resolves. Wired as
      `{"code scanning": ("CodeQL",)}`. An *unfinished* sentinel still yields pending, and real
      `Analyze` runs still win — the sentinel is only a fallback.
- [x] `_graphql` now surfaces body-level `errors` as workflow warnings, plus a
      `graphql_succeeded()` helper; the auto-merge call reports its **outcome**
      (`auto-merge: enabled` / a warning), never just the attempt.
- [x] 5 new tests in `test_pr_gate.py` (36 in that file, 172 repo-wide). Ruff clean.

## Open

- [ ] **Read the next run's log for the actual GraphQL error.** The fix makes the failure
      *visible*; it does not yet explain it. Likeliest candidates: the mutation is rejected when
      the PR is already mergeable with no pending required checks ("Pull request is in clean
      status"), or the repository ruleset declares no required status checks, leaving nothing for
      auto-merge to wait on. Repo-level `allow_auto_merge` is already `true`, and the workflow
      requests `pull-requests: write`, so neither of those is the cause.
- [ ] Backport to BlueprintX — `bin/pr_gate.py` and `tests.yaml` both ship from
      `templates/python-common`, so **every scaffolded project has all three bugs**.
